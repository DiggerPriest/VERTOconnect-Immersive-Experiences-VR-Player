# One-headset training hub test

This environment is optional until accepted. Keep the existing workshop panorama
selected on the other managed headsets. The test APK must have the same package
and signing certificate and a higher Android version code.

## Select and inspect

1. Start offline if practical. In Settings > Background select
   VERTOconnect Training Hub — Animated (wording may be shortened in the menu).
2. Wait for the loading message to clear. Turn fully around and lean gently while
   seated. The building must remain fixed in the world, with natural depth.
3. Select Look around; confirm the main panels hide. Select Return to menu using
   hand input. Repeat after turning toward a different bay.
4. Watch each worker through at least two complete routines. Check feet, joints,
   tool contact, pauses and loop transitions. Report the trade and approximate
   point in its routine for any defect.

## Existing flows

- Select and play a local360mono video. Verify scenery disappears and video starts
  at the beginning with the expected fully-out zoom and reset tilt.
- Return to library, open Talk to Jess, speak and hear the response. Close Jess and
  immediately select a video using hands. Repeat five times.
- Remove and replace the headset during video, in the library and during Jess.
  Confirm the existing restart/end-call behaviour and responsive hand pointers.
- Switch hub -> panorama -> hub repeatedly, then restart the app. Confirm the
  selected background is restored and no missing asset/frozen animation appears.

## Performance

With casting off, enable the optional session-only hub performance readout in
Background settings. Observe each direction and test for30minutes, including
several video/Jess returns. Record FPS, average/max frame interval and memory at
start and end. Target is the selected headset refresh rate, at least72FPS, without
sustained deterioration. App counters are not full GPU profiling; use OVR Metrics
or MQDH if managed-device access permits. Report discomfort or visible stutter.

Do not approve a default migration from these instructions alone. Ryan's visual
approval and observed headset results are required before making the hub default.
